# ADR 0003：主体属性快照进 JWT

- 状态：已接受
- 日期：2026-09-09

## 背景

PDP 判定时需要主体属性（department / clearance / region / title）。
两个选择：每个请求回查 auth-service，或登录时快照进 JWT claims。

## 决策

登录时把主体属性写进 JWT claims，每个请求自带，PDP 不回查。

## 理由

- **判定路径少一次网络往返**：授权在最热路径上，每个请求都要走
- **PDP 无状态**：不依赖 auth-service 可用性，PDP 挂不挂与身份服务解耦
- **属性量小**：四个字段，token 体积可控

## 代价（明确接受）

**属性不实时**：改了用户属性，旧 token 里还是旧值，要等下次登录才生效。
这在演示里是特性不是 bug——"改属性即改权限"的演示需要重新登录才能看到效果，
正好说明属性是跟身份绑定的。

生产环境要实时属性的正确做法：**不要**让每个请求等一个 RPC，
而是在 PDP 侧加短 TTL（如 30s）缓存回查目录服务（LDAP / HR 系统），
失效时降级用 JWT 里的旧值并告警。

## 备选方案

- **每请求回查 auth-service**：属性实时，但授权路径多一跳，
  auth-service 抖动会连累全站授权
- **网关回查后注入头**：省掉 PDP 的回查，但网关成了新的可用性单点，
  且业务服务直接调 PDP 时（行级过滤）拿不到属性
